\noindent The widespread adoption of deep learning models has driven significant technological advancements across domains such as healthcare, developer productivity, data analytics, and education. However, executing inference on infrequently accessed models, such as those hosted on platforms like Hugging Face, presents cost-efficiency challenges. Renting high-performance GPUs, like H100 or RTX 4090, for low-throughput tasks is economically impractical. Existing solutions like DynamoLLM~\cite{dynamollm} reduce costs by scaling GPU frequency and instances but lack support for heterogeneous vertical scaling across different hardware types.

This work addresses these limitations by proposing a containerized proxy server capable of dynamically selecting hardware resources based on cost-benefit analyses. Our approach improves throughput per dollar by routing requests to cheaper resources, such as RTX 4090 GPUs or CPU instances, for low-demand inference, while seamlessly switching to high-performance hardware to meet production throughput requirements. The system uses Docker containers to isolate inference workloads and llama.cpp as the inference engine, providing an OpenAI-compatible API that enables drop-in replacement for existing applications.

Implementing adaptive switching between CPU and GPU inference presents challenges in container orchestration, health monitoring, and workload routing. Our proxy server monitors real-time metrics including tokens per second, request rates, and hardware utilization to make informed scaling decisions. The system maintains separate container pools for different hardware configurations, enabling rapid transitions between resource types without service interruption.

By incorporating cost-benefit analysis into the routing layer, our system supports vertical scaling---dynamically switching between hardware types such as CPU, RTX 4090, or H100 GPUs based on workload characteristics. Evaluation demonstrates that this approach reduces cost per token for variable workloads while maintaining production-grade throughput when needed. The containerized architecture provides isolation, reproducibility, and seamless integration with existing cloud infrastructure and orchestration platforms.
